# simscope UI audit, 2026-09-30

**Status:** Findings, 2026-09-30. Audited against
[ui-guidelines.md](ui-guidelines.md) (rule IDs such as `T7` point there).

## Method

- The app at `http://127.0.0.1:8091` (`simscope serve`, the user's library:
  87 runs, 64 imported from Brax HTML and 23 from `.rbundle`, all single-env,
  all with only `body_pose`). Viewed in a fresh browser tab emulating
  1440 × 900 at DPR 2, in light and dark (T), with one run open
  (`a2_go2_sequential`, `d13_cad2_stage3_w050_h065`) and in compare (2 and 3
  runs).
- Computed styles, element sizes and overflow were read from the DOM; contrast
  and colour distances were computed with the `dataviz` skill's validator.
  "Seen" means it was visible in the screenshot; numbers in `code` were measured.
- Sources read: `web/src/app/` (App, Library, RunRowItem, ViewportToolbar,
  Pane, timeline/*, inspector/*, components/ui/*, app.css, DESIGN.md),
  `web/src/core/{ground,overlays}.js`, `docs/specs/2026-09-30-simscope-viewer-v3.md`.

## Findings by user point

### 1. Fonts: system mono readout and all-caps labels

- **Evidence.** Body is the system stack (`ui-sans-serif, -apple-system, …`) at
  `13.5px`. The time readout `0.00 / 7.98 s` is `ui-monospace, "SF Mono", …`
  `15px/500` under an all-caps `TIME` caption; the ruler, lane sub-labels,
  plot axes and plot values are also mono (9 call sites use `font-mono` or
  `pal.mono`). One single-run screen shows 12 uppercase, letter-spaced
  (`0.63px`) captions: Time, Frame, Duration, Frames, Rate, Envs, Bodies,
  Recorded, Curation, Notes, Streams, Export, plus `2 HIGHLIGHTS, CLICK TO ZOOM`
  in the hover card. Six sizes are in use (`10.5`, `11.5`, `12.5`, `13.5`,
  `15px`, and the 22 px `time` token), because `app.css` overrides Tailwind's
  `--text-*` scale, so shadcn components render smaller than designed.
- **Rules broken.** T1, T3, T4, T7, A4.
- **Change.** Bundle Geist (T2: `@fontsource-variable/geist@5.3.0`, latin
  `wght` woff2, 29,400 B, about 29 KB gzip, inlined as a data URI). Delete the
  `--text-*` overrides and the `.field-label` class; delete `font-mono` from
  the readout, plot header, `draw.ts` and uPlot axes and use `tabular-nums`.
  Captions become table keys or phrases (I7).

### 3. Cyan accent

- **Evidence.** `--signal` oklch(0.56 0.14 195) light / oklch(0.78 0.12 192)
  dark is used in 18 files: playhead flag, plot traces and plot playhead, tab
  underline, pressed toggles (`aria-pressed:bg-signal-soft text-signal`),
  selected row bar and fill, focus ring, checkbox, cluster pills, `Follow`
  text, pane outline, resize handles, loading bar. In dark mode the traces and
  playhead are the brightest things on screen. The dark ground checker is a
  saturated navy (`#33485f` / `#26384c` in `core/ground.js`).
- **Rules broken.** P4, C2, C5.
- **Change.** Neutral shadcn tokens (C1); `primary` neutral (C2); pressed =
  `bg-muted`; focus = neutral `ring`; tabs = `foreground` underline. Colour
  moves to data only: the eight-slot palette (C6–C9) for runs, pinned envs and
  highlight kinds. Neutral ground greys (C5). Delete `--signal`,
  `--signal-soft`, `--subtle`, `--star`, `--fav`; `--live` becomes
  `--destructive`.

### 4. Timeline

- **Evidence.** At the default 838 px timeline width the bar shows 14 buttons:
  `[Iso|Front|Side|Top] [⌖] [⌖ Position]` · `[◀] (▶) [▶]` · `TIME 0.00 / 7.98 s`
  · `[reel] [loop] [1× ⌄] [⌄]`. Container queries add zoom −/+/fit at
  ≥ 58 rem and ⏮/⏭ at ≥ 64 rem, so the bar changes shape whenever a sidebar is
  resized (seen at 958 px with the zoom group). The `Marks` lane is drawn on
  every run though this library has no marks. At the default 200 px height the canvas is
  `147px` tall and the two lanes end at `90px`: `57px` of empty strip. Lane
  fills are rounded `--lane` slabs at 60% opacity; single highlights are grey
  discs with a dark icon; clusters are cyan pills. The hidden frame field reads
  `0 / 399` while the Inspector says `400` frames. The hover card shows
  "Height drop · score 12 · 1.14 s · 1.161 m/s": a height drop measured in
  m/s, and an internal score.
- **Rules broken.** TL1–TL6, TL8, TL10, L5, I4, I10.
- **Change.**
  - Camera presets, Frame, Frame all and Follow collapse into one
    `DropdownMenu` styled like the speed menu (TL3).
  - The readout loses its caption: `2.49 / 7.98 s`, with the frame in the
    tooltip as `Frame 124 of 400` (TL2).
  - The `Marks` lane exists only when the run has marks (TL5).
  - The playhead is neutral (TL4); glyphs are drawn in their kind colours
    (TL6); lanes are hairline rows (TL11).
  - The zoom buttons go; `Fit` appears only while zoomed (TL10).
  - The timeline opens at its content height (L5).
  - The hover card uses the detector's `label` and `detail` (TL8). The
    in-progress `src/simscope/highlights.py` (format `simscope-highlights/2`)
    already emits kinds `landing`, `jump`, `fall`, `contact_spike` and
    `torque_spike`, each with a `detail` string such as
    `"412 N, 3.1× typical"`. The running server still serves the v1 signals
    (`height_drop`, `acceleration`). `features/timeline/icons.ts` maps only
    v1 keys, so v2 kinds would all fall back to the flag glyph. Map the v2
    keys to C8's glyphs.

### 5. Right panel: Plots first, Metadata as a table

- **Evidence.** Tabs are `Run · Plots` (Run first). The Run tab is a 3 × 2
  grid of uppercase `10.5px` captions over `13.5px/500` numbers (Duration
  7.98 s, Frames 400, Rate 50 Hz, Envs 1, Bodies 14, Recorded 5h ago), then
  Curation, Notes, Streams and two multi-line Export buttons ("Player page /
  Light, for decks and sharing" wraps to three lines at 320 px). The
  manifests hold richer metadata that is never shown: `meta.metrics`
  (`mean_reward`, `final_head_error_m`, `final_up_z`, …), `meta.config`, the
  original file path. "Recorded 5h ago" is the import time, not the recording
  time (see O8).
- **Rules broken.** I7, A1, A2, P2.
- **Change.** Tabs become `Plots` (default) · `Metadata` · `Envs` (only when
  envs > 1). Metadata is a shadcn `Table` with two columns and three sections:
  Run (duration, frames, rate, envs, bodies, recorded, simulator, source file,
  group, rating), Metrics (flattened `meta.metrics`, numbers right-aligned
  `tabular-nums` with units), and Config (collapsed). Streams appear as rows
  under Run. Notes follow the table. Export moves to the viewport (point 8).

### 6. Plots

- **Evidence.** Two `104px` uPlot charts (Height, Speed), each fully cyan with
  a `1.5px` cyan playhead that is hard to see on the cyan trace. Axes and the
  value readout are mono. "Click a plot to seek" is permanent hint text in
  `--subtle`. Below the two plots about 60% of the panel is empty.
- **Rules broken.** PL1, PL2, PL4, PL5, T3, T9.
- **Change.**
  - Trace in its slot colour up to the playhead, ending in an 8 px dot at the
    current value, `--ink-future` grey after (PL1, implemented per PL10).
  - Grey, draggable playhead (PL2); shared crosshair across plots (PL3).
  - Header `Height … 0.264 m` (PL4); x labels only on the last plot (PL5);
    120 px plots (PL7).
  - Delete the hint text: the cursor (`col-resize`) already says it.
  - Not verified: what exactly made the old viser plots feel better. viser
    also draws with uPlot (`add_uplot`), so the difference is styling, not
    the library.

### 7. Display options as overlay buttons

- **Evidence.** The top-right glass pill holds `[◉ Display ⌄] [☀]`. Display is
  one `DropdownMenu`: Ground (Checkerboard / Grid lines / None), Contact
  forces (C, disabled), Collision geoms (disabled), and Sync cameras in
  compare. Both checkbox items were disabled with no explanation (no run here
  has contacts or collision geoms).
- **Rules broken.** V1–V3, I6, P6.
- **Change.** The toolbar of V1: `Ground ▾` (toggle plus a popover with
  Checkerboard / Grid), and `Visual`, `Collision` and `Contacts` icon toggles,
  each disabled with its reason. `Sync cameras` is a toggle shown only in
  compare. Contact arrows use `--kind-contact`; collision geoms are neutral (C9;
  core constants in `overlays.js` `#e4572e`, `#f2b134`, `#2a9d8f` and
  `scene.js` `#ff8a3d`).

### 8. Export in the viewport toolbar

- **Evidence.** Export is the last section of the Run tab, below Notes and
  Streams: you have to scroll to reach it, and the two buttons are 3-line cards.
- **Rules broken.** A2, P6.
- **Change.** An `Export ▾` `DropdownMenu` in the viewport toolbar (V4). Its
  two items carry their descriptions as a second line and export the open run
  or the compared set.

### 9. Library: date sections, a handful per group, groups instead of tags

- **Evidence.** One flat virtual list of 87 two-line rows (`52px` each,
  about 14 rows visible). Filters: favourites, status, sort, and two tag chips
  that are both machine tags. End-truncation makes rows indistinguishable:
  four rows read `go2-crate_climb-upstr…` and four `go2-seq_jump-upstre…`;
  10 of the visible names were clipped at the 220 px width. Every run's
  `created` is 2026-09-30 (the import time) although the source files date
  from 2026-09-10 to 2026-09-23, so date sections today would be a single
  `Today` group of 87 (O8).
- **Rules broken.** I8, L4, P6.
- **Change.**
  - shadcn `Sidebar` with `Collapsible` `SidebarGroup`s. A `Date | Group`
    `ToggleGroup` switches the view. Date buckets are Today / Yesterday /
    Previous 7 days / Previous 30 days / months; group view is user groups
    A–Z plus `Ungrouped`. Each group shows 5 rows then
    `Show N more` (`SidebarMenuButton size="sm"`). Sticky headers carry a
    `SidebarMenuBadge` count. Rows are one line, 32 px (name middle-truncated,
    duration right, `tabular-nums`).
  - `Pinned` sits above the sections and replaces favourites.
  - Moving runs: a row `ContextMenu` (`Move to group ›`, `New group…`,
    `Remove from group`), the same items in the pick bar for several runs,
    and drag onto a group header.
  - Storage: a run has at most one group. This needs an annotations op
    (`group`) replacing `tag_add` / `tag_remove`; the backend is not designed
    here.

### 10. Compare: the selection bar and run colours

- **Evidence.** With the library at `220px`, two picks produce the bar
  `2 / selected / Up / to / 4 / runs` stacked one word per line: the text
  column shrinks to `16px` beside `Clear` (49 px) and `Compare` (90 px). The
  library column's content becomes `245px` wide and scrolls sideways by `25px`,
  clipping the first letters of every run name (`_cad_sequential`); it stayed
  scrolled after opening compare.
  At 280 px it fits. Compare panes have no identity colour: an active pane is
  a cyan 1 px ring, names are only in bottom-left pills, and the timeline shows
  only the active pane's highlights. Three panes are laid side by side
  (`279 × 699px` each at 1440) and the robot is cropped.
- **Rules broken.** L3, C6, C7, TL7, V6.
- **Change.**
  - The pick bar is one line: `● A ● B  2 runs  [Clear] [Compare]`. The
    4-run limit is only stated when a fifth checkbox is disabled, in its
    tooltip "Compare takes up to 4 runs".
  - Each picked run takes the next free slot A–D at pick time and keeps it.
    The dot and letter show on its row, its pane header (`● A name ×`), its
    timeline lane (one lane per run, glyphs in the run colour, shape by
    kind) and its plot trace. The active pane gets a 2 px ring in its own
    colour.
  - Three panes use the 2 × 2 grid with an empty fourth cell, so no pane is a
    sliver.

### 11. A guide

- **Change.** [ui-guidelines.md](ui-guidelines.md): one-line rules with
  sources (NN/g, Refactoring UI, Laws of UX, Apple HIG, Tufte, WCAG, shadcn
  source), the validated palette, the component map and a 15-item screenshot
  checklist. `web/src/app/DESIGN.md` should shrink to a pointer at it plus the
  layout facts that stay (panel sizes, persistence).

## Other findings

- O1. **Low-contrast text.** `--subtle` text (captions, units, hints, the
  `87` count) measures `2.88:1` on the light sidebar and `3.35:1` on the dark
  sidebar, below 4.5:1 (T9, WCAG 1.4.3). Use `muted-foreground` (shadcn
  neutral: `4.74:1` on white, `7.66:1` on dark).
- O2. **Default sizes depend on the window at first load.** A tab first opened
  in a narrower window and then set to 1,440 px kept the library at `220px`
  and the panel at `260px` (both minimums, since defaults are `0.195 ×` and
  `0.222 ×` the load-time width), where the pick bar and `Status` button
  break. L2's minimums (240/280) and L3's minimum-width test catch this.
- O3. **Run names lose the part that differs** (L4; point 9).
- O4. **The empty-viewport hint lists "H highlight reel"** among five
  shortcuts. Replace it with "Choose a run from the library, or press N"
  (K5).
- O5. **The `Following base` chip** (bottom-right) restates the Follow menu. Show
  follow state in the camera trigger (V5).
- O6. **Glass overlays** use `backdrop-filter: blur(14px) saturate(1.4)` over
  the WebGL canvas: extra GPU work for decoration (V7).
- O7. **The list skeleton and the pane loading bar shimmer in a loop** next to
  the pulsing `LIVE` dot (M3). Only the recording dot may loop.
- O8. **Imported runs have no recording time.** `rollout.json` `created` is the
  import time for all 87 runs; `source.original` points at files modified
  2026-09-10…23, and rbundle names embed `20260910T003806…Z`. The importers
  should store the source time (file mtime or the embedded stamp) as
  `recorded`; date sections and the Metadata `Recorded` row use it.
- O9. **The frame count disagrees:** the readout's frame field says `/ 399` (last
  index) while the Inspector says `400` (count). Use `Frame 124 of 400`
  everywhere.
- O10. **The plot channel picker** defaults to Height and Speed for every run;
  with only `body_pose` recorded, the Plots tab cannot show anything else.
  That is correct, but the empty space under the two plots should say so in
  one line: "This run recorded only body poses" (K5).
- O11. **Dark mode** draws the cyan traces and playhead at `L 0.78`, the
  brightest elements on screen, above the robot. With C2 the brightest
  element is the data.

## Order of work

1. Tokens and type: Geist, Tailwind's default scale, shadcn neutral, the
